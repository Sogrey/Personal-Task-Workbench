### FIX-6 任务状态管理增加「延期处理」+ 逾期自动标识（P1）✅

* 背景（用户需求 2026-11-17）：当前 `overdueTasks` 逾期只出现在提醒页/报告风险节，任务本身无状态可查；且闭环确认（PRD §5.11）与延期标识是两套动作，用户希望进入状态流统一管理。
* 改动：
  1. **新增任务状态枚举 `delayed`（延期处理）**：`types/index.ts` `TaskStatus` + `statusLabel` 映射「延期处理」；`status.ts` 配色（建议紫 `#8b5cf6`，与色板待确认项统一考虑）；任务列表状态筛选、状态下拉（新建/编辑/列表行内/抽屉）、徽章全部补齐。
  2. **逾期自动标识（派生，非存储）**：保留 `delayed` 枚举与既有 `task.delayed` 布尔打标并存：`overdueTasks` 判定不变（截止 < 今天且未完成）；新增派生集 `overdueTaskIds`，凡进入该集且状态非 done/cancelled/delayed 的任务，在任务列表、抽屉、周视图块统一自动叠加「逾期 N 天」红色徽章——数据层不写库、不产生历史留痕，随时间自然恢复（跨天后自动消失）。
  3. **闭环向导联动**：周报/月报风险节的「逾期」组与状态徽章同源；闭环确认"延期"时除打 `task.delayed` 标外同步把状态置为 `delayed`，报告「已确认延期」口径合并两者去重。
  4. **历史留痕**：状态切换到/切出 `delayed` 走既有 `updateTaskStatus` 自动留痕，「逾期自动标识」为派生显示不留痕。
* 边界：旧数据无 `delayed` 状态值，无迁移问题（枚举新增向后兼容）；`filtered` 列表当前排除 cancelled，`delayed` 状态任务正常显示。
* 验收：状态四处（筛选项/下拉/徽章/报表）齐备；构造截止昨天的任务未完成 → 列表、抽屉自动出现「逾期 1 天」徽章，补录完成后消失；闭环确认延期 → 状态=延期处理 + 抽屉延期说明同现；提醒页/周报数据与徽章一致。
* 验证：e2e 22 项相关断言通过——状态四处齐备（筛选/列表行内/表单/抽屉）；逾期徽章派生显示且延期任务不计数；闭环确认延期→状态联动 delayed+打标+留痕（状态变更→延期处理）；周报/日报逾期与已确认延期口径合并去重（确认前 2/2，确认后 1/3）；旧数据仅打 delayed 标兼容不误报（2026-11-18）。
