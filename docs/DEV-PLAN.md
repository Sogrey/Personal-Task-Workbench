## 2. 当前迭代 · FIX 系列（高优先级修补）

来源：用户实测反馈（2026-11-17 截图反馈五项 + 状态管理需求一项）。优先级高于 M5/AI 增强，按 FIX-1 → FIX-6 顺序实施（FIX-6 为状态模型扩展，依赖 FIX-1~5 合入后再动 store/状态机，避免同文件冲突）。需求背景与验收标准详见 PRD §9.1（本节为执行摘要）。

- 验收：日报/周报/月报 Markdown 与视图模式均无逐条时间段；标题含负责人恰一次。
- 验证：e2e 日报标题带署名恰一次；完成/进行中条目均为 `任务名（项目）` 且无时段、负责人后缀（2026-11-18）。

### FIX-2 负责人动态化（P0）✅

- 验收：设置页改负责人 → 新建表单默认值同步、报告标题变化、编辑旧任务不受影响。
- 验证：e2e 设置页读取偏好负责人、新建表单预填、报告标题署名同源联动（2026-11-18）。

### FIX-3 表单时间语义说明与先后校验（P1）✅

- 改动：新建/编辑表单时间三字段下加说明文案（开始/结束=计划执行时段；截止=完成期限）；开始>结束 → 硬校验拦截保存；截止<开始 → 软警示允许保存，任务列表行内常驻警示。
- 验收：乱序被拦截/警示；文案两表单均可见；历史乱序数据不阻塞使用。
- 验证：e2e 结束早于开始→保存按钮禁用+硬警示；截止早于开始→软警示可保存；保存后列表行常驻「⚠ 截止早于开始」（2026-11-18）。

### FIX-4 周视图跨天任务跨列延续（P1）✅

- 改动：`WeeklySchedule.vue` 归列逻辑（现 `t.startAt.slice(0,10) === key`，第 148 行）改为按覆盖日期逐日渲染；每日块取当日时段（首日 14:00–轴末、次日轴首–18:00），块内加「跨天」标记；重叠簇算法每日独立计算。
- 验收：跨天任务两列都有块且时段正确；点击任一列块可开面板/详情；冲突检测不回归。
- 验证：e2e 跨天任务昨/今/明三列延续，首日 `16:00–18:00 ⇢`、中间日 `⇠ 全天 ⇢`、尾日 `⇠ 08:00–11:00`，均带「跨天」标（2026-11-18）。

### FIX-5 时间显示补日期（P1）✅

- 改动：今日时间线条目补 `M/D`；悬浮卡/重叠簇面板对跨天任务显示完整起止（`11/16 14:00 – 11/17 18:00`），当天任务保持 HH:mm；周视图单日块内保持 HH:mm（列头即日期）。
- 验收：脱离列头/上下文可读出日期；跨天任务任一总览视图可辨识跨度。
- 验证：e2e 时间线跨天任务 `11/18 00:00 – 11/19 10:00`、同日任务保持 `09:00–10:30` 紧凑格式（2026-11-18）。

### FIX-6 任务状态管理增加「延期处理」+ 逾期自动标识（P1）✅

- 背景（用户需求 2026-11-17）：当前 `overdueTasks` 逾期只出现在提醒页/报告风险节，任务本身无状态可查；且闭环确认（PRD §5.11）与延期标识是两套动作，用户希望进入状态流统一管理。
- 改动：
  1. **新增任务状态枚举 `delayed`（延期处理）**：`types/index.ts` `TaskStatus` + `statusLabel` 映射「延期处理」；`status.ts` 配色（建议紫 `#8b5cf6`，与色板待确认项统一考虑）；任务列表状态筛选、状态下拉（新建/编辑/列表行内/抽屉）、徽章全部补齐。
  2. **逾期自动标识（派生，非存储）**：保留 `delayed` 枚举与既有 `task.delayed` 布尔打标并存：`overdueTasks` 判定不变（截止 < 今天且未完成）；新增派生集 `overdueTaskIds`，凡进入该集且状态非 done/cancelled/delayed 的任务，在任务列表、抽屉、周视图块统一自动叠加「逾期 N 天」红色徽章——数据层不写库、不产生历史留痕，随时间自然恢复（跨天后自动消失）。
  3. **闭环向导联动**：周报/月报风险节的「逾期」组与状态徽章同源；闭环确认"延期"时除打 `task.delayed` 标外同步把状态置为 `delayed`，报告「已确认延期」口径合并两者去重。
  4. **历史留痕**：状态切换到/切出 `delayed` 走既有 `updateTaskStatus` 自动留痕，「逾期自动标识」为派生显示不留痕。
- 边界：旧数据无 `delayed` 状态值，无迁移问题（枚举新增向后兼容）；`filtered` 列表当前排除 cancelled，`delayed` 状态任务正常显示。
- 验收：状态四处（筛选项/下拉/徽章/报表）齐备；构造截止昨天的任务未完成 → 列表、抽屉自动出现「逾期 1 天」徽章，补录完成后消失；闭环确认延期 → 状态=延期处理 + 抽屉延期说明同现；提醒页/周报数据与徽章一致。
- 验证：e2e 22 项相关断言通过——状态四处齐备（筛选/列表行内/表单/抽屉）；逾期徽章派生显示且延期任务不计数；闭环确认延期→状态联动 delayed+打标+留痕（状态变更→延期处理）；周报/日报逾期与已确认延期口径合并去重（确认前 2/2，确认后 1/3）；旧数据仅打 delayed 标兼容不误报（2026-11-18）。

## 4. 工程惯例（每轮迭代生效）

- 时间规范：datetime 值一律无时区本地 ISO；禁止 `toISOString()`；禁用 PowerShell 处理含中文源码文件；禁用 `git checkout -- <file>` 恢复。
- 验收门槛：`npm run type-check` + `npm run lint` 零错误；涉及 UI 的改动用无头 Edge + CDP 实测（几何断言优先于图像识别）；dev server 与测试进程归属核对后清理。
- 提交规范：Conventional Commits，主题化分批、按依赖链排序（基础设施→功能→文档）；推送与打标签前向用户确认。
